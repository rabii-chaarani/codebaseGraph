## New confirmed PR defect: macOS nested enumeration loses later entries

**P2.** [The new macOS `RootedDirectory` traversal](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/locks.rs#L2552-L2563) resets and consumes the retained directory FD with `lseek`/`getattrlistbulk`. Its [callback](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/locks.rs#L2616-L2620) can traverse the same anchor and consume the caller's kernel cursor. After its buffered batch, the outer traversal sees EOF and silently omits later entries. `RootedDirectory` and `visit_entries` are absent from the specified base: this is a **new PR defect**, not an older platform gap.

The executed reviewer fixture includes the **unmodified exact-head** `src/storage/test_harness.rs` and, through it, `locks.rs`; it does not substitute a reimplemented scanner. It links against freshly built exact-checkout dependencies. With 200 files and 4096-byte scratch buffers, baseline traversal saw 200, every complete nested traversal saw 200, but outer traversal saw **85**. The completeness assertion failed (exit 101). **85 is the measured first-batch count, not a portable limit.**

Production performs this nesting: [`prepare_terminal_output` scans the registry](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/maintenance_candidate.rs#L2717-L2724) and [calls `workspace_has_child_receipts` on that same registry](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/maintenance_candidate.rs#L2780-L2793), whose [inner traversal](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/maintenance_candidate.rs#L2658-L2668) consumes it. Later receipts can be skipped in a multi-batch directory, leaving terminal cleanup pending. **No unsafe deletion, data loss or full-collector starvation/convergence failure was reproduced.**

Planning direction: keep the pinned directory as namespace authority but give each enumeration an independent open file description, for example rooted `openat(".")` with appropriate flags. `dup`/`try_clone` shares cursor state and is insufficient. [Windows already reopens its pinned directory per traversal](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/storage/locks.rs#L2688-L2692). Preserve that boundary; require a multi-batch macOS nested regression and a production receipt-selection test before claiming cleanup convergence.

- **Windows runtime dependencies (P2):** both exact-head bundled JSON/FTS PE assets import `libssl-3-x64.dll`, `libcrypto-3-x64.dll`, `MSVCP140.dll`, `VCRUNTIME140.dll`, and `VCRUNTIME140_1.dll`. Static OpenSSL linking of an EXE does not satisfy a separately loaded extension's import table. Evidence is **current checked-in asset inspection and source policy**, not a clean-Windows missing-DLL reproduction. Choose a documented/checked prerequisite policy or verified application-controlled dependency packaging.
- **macOS runtime dependencies (P2):** [preexisting dynamic OpenSSL link/search policy](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/build.rs#L8-L26), with no packaging relocation step, remains. `otool -L` on the fresh exact-head **debug** CLI shows absolute `/opt/homebrew/opt/openssl@3/lib/libssl.3.dylib` and `libcrypto.3.dylib` imports. **This is not a release-artifact inspection or clean-consumer launch.** Qualify the final installed archive after selecting bundling/static-link/prerequisite policy.
- **Windows discovery (P2; preexisting source):** [unchanged helpers](https://github.com/rabii-chaarani/codebaseGraph/blob/862a8f88d485d5bd257ebd9456c194156fd4ee94/src/api/lifecycle.rs#L5060-L5073) use HOME-or-`.` and exact executable filenames.
