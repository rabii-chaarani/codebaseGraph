Its MCP test source is byte-identical to branch baseline`8f25fde6659e9adbfee10f16a5f4d072bb2e8d91`. [Identity](pr164-macos-unit-evidence/identity.json), [hosted log](pr164-macos-unit-evidence/job.log), [native report](pr164-macos-unit-evidence/native-test-report.json).

`RUST_TEST_THREADS=1` and stdio's sequential dispatcher rule out concurrent requests from this fixture. Autonomous maintenance shares the coordinator's execution slot and can legitimately reject a request with typed`graph_busy`, `retryable=true`, before execution. An unreadable graph alone instead produces a successful health response with`ok=false`. The original Boolean failure does not identify which API/runtime/transport error occurred: **maintenance contention is a supported mechanism, not a confirmed diagnosis of the archived macOS response**. [Independent diagnosis](pr164-macos-unit-evidence/diagnosis-review.md).

## Test-only correction

- Replace the preloaded Cursor transcript in this one test with a loopback duplex fixture running the unchanged stdio server in one scoped thread/session.
- Repeat only the same request rejected before dispatch: method`tools/call`, matching response ID/tool, `isError=true`, exact structured code`graph_busy`, boolean`retryable=true`. Never repeat a successful request, a whole transcript, timeout/disconnect or another retryable error. Add structured metadata to the search request while retaining its JSON text assertions.
- Preserve all five terminal response checks: protocol/tool schema, readable health, refresh enabled/backend, actual search result, and expected mutation rejection. The expected graph_query error is not retried. Full health response is now printed on failure.
- Add matcher negatives for wrong ID/tool, success, transport error, false/null/string retryable and initialize. Add a deterministic real-coordinator regression: hold its actual maintenance permit, verify health rejected with graph_busy/retryable and zero executions, channel-release it, then verify same-client health succeeds with exactly one execution. No sleeps or scheduling luck in that regression.
- **New test-only policy:** one fixed15-second admission-retry budget starts before the first protocol frame and is never renewed. Client socket read/write timeouts use remaining budget; this is per-I/O behavior, not a strict total wallclock/cancellation guarantee. RAII shutdown closes both directions before scoped join on success/panic. No production timeout, retry policy, source, workflow, dependency or acceptance change.

This is a bounded correction of an independently demonstrated test scheduling assumption. A later macOS failure with another error remains a failure, now with useful diagnostics. No claim that the unrecorded original error was graph_busy is made.
