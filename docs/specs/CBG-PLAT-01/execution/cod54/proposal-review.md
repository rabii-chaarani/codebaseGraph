### SC-02 — Keep native auditing out of cross-target validation

**Status: resolved in the revised contract.** `validate_native_artifact_set` currently extracts/checksums every target on its caller's host (`main.rs:683–764`). A macOS-only `otool`/`codesign` audit cannot be unconditionally inserted there without breaking cross-target validation. The final `validate_package` contract explicitly confines it to matching native macOS build/execution paths; inventory/checksums remain host-independent. No replacement framework is needed.

### SC-03 — Prove installed behavior without inherited runtime assistance

**Status: specified; execution pending as part of implementation verification.** Draft1 line17 correctly requires installed smoke with an empty extension cache. Existing smoke helpers directly inherit environment and include separately created MCP/HTTP processes (`main.rs:1662–1777,1782,1848,2098,2206–2313`). Source cache seeding uses macOS `HOME` and skips existing extension files (`src/db_writer/extensions.rs:10–37,63–71`). Therefore setting one parent variable or cleaning only `run_checked` would not prove isolation.

The final contract addresses this with per-child command configuration: remove every `DYLD_*`, remove caller OpenSSL configuration overrides, use controlled system PATH for smoke only, and reuse the same fresh HOME across graph/reopen/search and MCP children. Keep build/tool environment separate. Install into a spaced path, then execute the installed pair. Verify JSON/FTS use the bundled bytes in the fresh cache rather than treating generic CLI help as extension evidence. Actual final installed checks, including missing/corrupt/incompatible sidecars and destination preservation, remain required—not already passing because scratch launch passed.
