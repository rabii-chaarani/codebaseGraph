## Why packaging only at CLI build/link time is insufficient

`build.rs` presently dynamically links `ssl` and `crypto` and searches producer Homebrew paths (`/opt/homebrew/opt/openssl@3/lib`, `/usr/local/opt/openssl@3/lib`) when `OPENSSL_LIB_DIR` isn't set. `crates/xtask` currently stages only the two executables and two installer scripts plus binary checksums; it archives an exact five-file allowlist. Thus adding a linker search dir or editing just the CLI import names cannot provide the runtime libraries: the executables will still fail on a clean consumer if the sidecars are absent. The two dylibs plus license/checksum/archive allowlist and relative resolution must be part of each prebuilt macOS artifact. No extension sidecars need separate bundling: the actual macOS extensions are already compressed into product binaries, seeded byte-for-byte into Ladybug cache and import only Apple system dylibs.
