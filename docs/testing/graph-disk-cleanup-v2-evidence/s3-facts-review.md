## Consequential hypotheses checked

**Unsafe allocation and reference lifecycle.** Reviewed every unsafe block and both manual Send/Sync implementations in `maintenance_budget.rs:17–198`. The Account has one nonzero `Layout::new::<Account>()` allocation, initialized before publishing a handle, and deallocated with the same layout by the last reference. All mutable shared Account fields are atomic; `limit` is immutable. Cloning uses a relaxed atomic increment with an abort threshold below `usize::MAX`. Final release uses Release decrement plus Acquire fence before dropping/deallocating the Account. This follows the applicable ownership/order pattern described by the [Rustonomicon clone](https://doc.rust-lang.org/nomicon/arc-mutex/arc-clone.html) and [drop](https://doc.rust-lang.org/nomicon/arc-mutex/arc-drop.html) chapters; it does not introduce weak references or mutable access to Account data.

Checked-add/CAS reserves charges before byte allocation. Split moves an existing charge without duplicating it; reservation has no Clone. Fallible allocation and oversized layouts unwind the consumed reservation. Exact byte layouts are validated; the zero-length path uses an aligned dangling u8 pointer without allocation/deallocation. Unique mutable access requires `&mut self`; immutable shared access and movement between threads respect the manual traits. ReservedBytes deallocates its bytes in its Drop body, before the reservation field releases its charge. No unsafe defect survived source tracing and isolated failure/lifecycle probes. Refcount saturation itself was reviewed statically, not reached dynamically.

**Ceiling under contention and grant boundaries.** CAS failures retry against the current used count. A reservation keeps its Account alive after original handles are dropped. Sixteen synchronized two-thread races attempted to reserve the entire same remaining ceiling: exactly one succeeded per race, peak never exceeded the ceiling, and used returned to the fixed floor. MutationGrant is neither Send nor Sync. Its time check permits the last successfully reserved entry, while ordinary check/take rejects new entry 101; rejected multi-entry requests do not reduce the allowance. Time is cooperative and checked before starting work, not a syscall deadline. No authority or filesystem operation exists in these primitives.

**Lexical tokenizer facts.** Audited object/array state transitions, trailing data, number syntax, UTF-8 validation, surrogate pairs, checked offsets/decoded lengths, token spans and hashes in `maintenance_json.rs`. Buffer allocation is fixed at 4096 bytes; container state is fixed at 127. The ordinary artifact loader uses `serde_json::from_reader` without disabling recursion. Cargo.lock pins serde_json 1.0.150; its actual source initializes depth 128 and rejects decrement-to-zero, matching the implemented 127-container boundary ([pinned primary source](https://docs.rs/serde_json/1.0.150/src/serde_json/de.rs.html)). Independent object and array fixtures tested depths 1–130; short reads, Interrupted retries, UTF-8/escape crossings around offset 4096, malformed inputs, decoded digests and exact spans were exercised.

Hashes remain raw and whitespace-stripped lexical hashes. Object order is not sorted or semantically canonicalized. The isolated differential harness deliberately enabled serde_json `preserve_order`. Unicode escape flags are conservative facts, not a complete producer recognizer. Lexically valid numbers may exceed typed loader range; nonfinite serialized null, defaults, duplicate keys, raw-row joins and schema compatibility remain outside usable-backup/origin authority. Existing tests and comments accurately retain those distinctions.

**Cursor selection and codec.** Audited fixed layout, magic/version, category bounds, checksum, canonical zero slots and installation binding in `maintenance.rs`. Selection retains the next lexicographic logical address per category and wraps; `inspected` advances for blocked candidates and rotates categories. Reverse enumeration, all eight categories, repeated codec reconstruction, wrap and every single-byte corruption were tested. Addresses must remain lossless caller-supplied logical identities. The codec has no persistence, path resolution, origin or deletion authority. Simulations establish only pure selection behavior.
